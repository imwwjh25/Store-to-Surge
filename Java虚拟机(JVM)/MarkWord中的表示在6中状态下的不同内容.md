# Java 中 Mark Word 在 6 种状态下的完整内容

Java 对象头的**Mark Word**是实现**synchronized 锁升级**、GC 标记、哈希码的核心数据结构，**64 位 JVM**（主流）和 32 位 JVM 结构不同，下面只讲**生产环境必备的 64 位 JVM**规范。

Mark Word 总长度：**64 bit**

6 种状态：**无锁、偏向锁、轻量级锁、重量级锁、GC 标记、可偏向 (匿名偏向)**

------

## 核心前置知识

1. 锁状态标志位 + 偏向锁标志位

   ：唯一决定 Mark Word 状态

   - `偏向锁标志位(1bit)` + `锁状态标志位(2bit)` = 3 位确定状态

   

2. 64 位 JVM 默认开启**指针压缩 (-XX:+UseCompressedOops)**，Mark Word 结构如下：

表格







| 状态总数 |   官方 6 种状态   |
| :------: | :---------------: |
|    1     |       无锁        |
|    2     | 可偏向 (匿名偏向) |
|    3     |      偏向锁       |
|    4     |     轻量级锁      |
|    5     |     重量级锁      |
|    6     |      GC 标记      |

------

# 6 种状态 Mark Word 完整结构（64 位 指针压缩开启）

## 1. 无锁状态（未加锁、未计算 hashcode）

- **标志位**：偏向锁`0` + 锁状态`01`
- **用途**：新建对象，未调用`hashCode()`，未加锁

plaintext











```
[ 25bit未使用 ][ 31bit分代年龄(4) + 分代垃圾回收标记 ][ 偏向锁0 ][ 锁状态01 ]
```

- 无 hashcode、无线程信息，纯空状态

## 2. 无锁状态（已计算 hashcode）

- **标志位**：偏向锁`0` + 锁状态`01`
- **用途**：调用过`obj.hashCode()`的无锁对象

plaintext











```
[ 25bit未使用 ][ 31bit hashcode ][ 4bit分代年龄 ][ 偏向锁0 ][ 锁状态01 ]
```

- 核心：存储**对象原生 hashcode**

## 3. 可偏向 (匿名偏向) 状态（JDK 默认初始状态）

- **标志位**：偏向锁`1` + 锁状态`01`
- **用途**：新建对象，**JDK 默认开启偏向锁**，还没有线程持有偏向锁

plaintext











```
[ 54bit未使用 ][ 2bit未使用 ][ 4bit分代年龄 ][ 偏向锁1 ][ 锁状态01 ]
```

- 无线程 ID，等待第一个线程来抢占偏向锁

## 4. 偏向锁状态

- **标志位**：偏向锁`1` + 锁状态`01`
- **用途**：单线程反复加锁，无竞争，最高效

plaintext











```
[ 54bit 持有锁的线程ID ][ 2bit 偏向时间戳(epoch) ][ 4bit分代年龄 ][ 偏向锁1 ][ 锁状态01 ]
```

- 核心：存储**持有锁的线程 ID**，无需 CAS 竞争

## 5. 轻量级锁（自旋锁）状态

- **标志位**：锁状态`00`（无偏向锁位）
- **用途**：多线程短时间竞争锁，线程自旋等待

plaintext











```
[ 62bit 指向栈中锁记录(Lock Record)的指针 ][ 锁状态00 ]
```

- 核心：指向**线程栈的锁记录**，用 CAS 更新指针

## 6. 重量级锁（互斥锁）状态

- **标志位**：锁状态`10`（无偏向锁位）
- **用途**：锁竞争激烈，线程阻塞（内核态）

plaintext











```
[ 62bit 指向重量级锁Monitor对象的指针 ][ 锁状态10 ]
```

- 核心：指向**ObjectMonitor**（管程），JVM 底层实现阻塞 / 唤醒

## 7. GC 标记状态（标记 - 清除算法标记）

- **标志位**：锁状态`11`（无偏向锁位）
- **用途**：GC 垃圾回收时标记对象

plaintext











```
[ 62bit GC标记信息/转发地址 ][ 锁状态11 ]
```

- 该状态下**所有业务数据全部清空**，只保留 GC 信息

# 最简记忆表（面试 / 开发必背）

表格







|     锁状态     | 偏向锁位 (1bit) | 锁状态位 (2bit) | 核心存储内容  |
| :------------: | :-------------: | :-------------: | :-----------: |
| 无锁 (无 hash) |        0        |       01        |      空       |
| 无锁 (有 hash) |        0        |       01        | 对象 hashcode |
|     可偏向     |        1        |       01        |      空       |
|     偏向锁     |        1        |       01        |    线程 ID    |
|    轻量级锁    |        -        |       00        | 栈锁记录指针  |
|    重量级锁    |        -        |       00        | Monitor 指针  |
|    GC 标记     |        -        |       11        |    GC 信息    |

------

### 总结

1. **3 位标志位定状态**：1 位偏向锁 + 2 位锁状态
2. **无锁 / 可偏向 / 偏向锁共用 01 状态**，靠偏向锁位区分
3. **轻量 / 重量 / GC** 无偏向锁位，直接用 2 位状态区分
4. 只有**无锁 (有 hash)** 存 hashcode，**偏向锁**存线程 ID，**加锁后 hashcode 存在 Monitor 中**
