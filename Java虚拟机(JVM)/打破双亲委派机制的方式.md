# 一、打破双亲委派的 **3 种核心方式**（必须背）

## 1. **重写 `ClassLoader.loadClass()` 方法（最根本）**

这是**最标准、最底层**的打破方式。

### 原理

`loadClass()` 默认实现就是**双亲委派逻辑**：

1. 先找缓存
2. 没有 → 交给父加载器
3. 父加载器找不到 → 自己加载

**只要重写这个方法，不交给父加载器，就直接打破双亲委派。**

### 代码样子

java



运行









```
@Override
protected Class<?> loadClass(String name, boolean resolve) throws ClassNotFoundException {
    // 不调父类加载器，自己直接加载
    // 这就打破了！
}
```

### 使用场景

Tomcat、热部署、OSGi、自定义类加载器。

------

## 2. **使用 \**线程上下文类加载器（Thread.getContextClassLoader ()）\**（最常用）**

这是 **SPI（JDBC）** 打破双亲委派的方式。

### 原理

- 父类加载器（Bootstrap）**拿不到**子类加载器（App）的类
- 所以把 **AppClassLoader 放进线程里**
- 让父加载器**反过来用子加载器** → 打破向上委派

### 核心代码

java



运行









```
// 获取线程上下文类加载器（默认是 AppClassLoader）
ClassLoader cl = Thread.currentThread().getContextClassLoader();
```

### 使用场景

JDBC、Spring、Dubbo、所有 SPI 机制。

------

## 3. **使用 `Class.forName(className, initialize, loader)` 指定加载器**

手动指定类加载器，**绕开默认的双亲委派**。

### 原理

`Class.forName` 默认用**调用者的类加载器**

但你可以**手动传一个自定义加载器**，强制用它加载。

------

# 二、一句话总结 3 种方式

1. **重写 loadClass ()** → 从根源破坏双亲委派
2. **线程上下文类加载器** → 父加载器反向用子加载器
3. **Class.forName 指定加载器** → 手动指定，绕开默认机制

------

# 三、面试官最爱问：**哪种是 SPI 用的？哪种是 Tomcat 用的？**

你直接背：

- **SPI（JDBC）** → **线程上下文类加载器**
- **Tomcat / 热部署** → **重写 loadClass ()**

------

# 四、面试满分回答（直接背）

打破双亲委派机制主要有 **3 种方式**：

1. **重写 ClassLoader 的 loadClass () 方法**

   不按照默认的双亲委派逻辑执行，不交给父类加载器，自己直接加载类。

   Tomcat、自定义类加载器都用这种。

   

2. **使用线程上下文类加载器（Thread.getContextClassLoader ()）**

   让顶层的父类加载器，可以获取并使用底层的子类加载器，实现反向加载，打破向上委托。

   JDBC 的 SPI 机制就是用这种方式。

   

3. **通过 Class.forName () 手动指定类加载器**

   绕过默认的类加载器，强制使用指定的加载器加载类。

   

------

### 总结（最核心 2 个）

90% 面试只问这两个：

1. **重写 loadClass ()** → Tomcat、自定义加载器
2. **线程上下文类加载器** → SPI、JDBC
