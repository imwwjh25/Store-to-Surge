### ZGC 着色指针（Colored Pointers）核心原理详解

着色指针（Colored Pointers）是 ZGC 实现「超低延迟」「并发回收」的**最核心技术**，也是 ZGC 区别于 G1、CMS 等传统 GC 的关键。简单来说：**着色指针是在对象的内存地址（指针）中嵌入额外的「标记位」（颜色信息），通过这些标记位直接管理对象状态，无需在对象头中存储元数据，从而实现全并发的垃圾回收**。

下面从「为什么需要着色指针」「指针结构」「核心原理」「实际应用场景」四个维度拆解，全程用通俗的语言 + 实例说明，避免纯理论抽象。

## 一、先理解：传统 GC 的痛点（着色指针要解决的问题）

传统 GC（如 G1、CMS）管理对象状态的方式是「在对象头中存储标记信息」：

- 对象头包含「标记位」（如是否存活、是否被移动）、「哈希码」「锁信息」等；
- 当 GC 并发标记 / 移动对象时，需要修改对象头的标记位，但应用线程也可能同时访问 / 修改对象头，为了避免冲突，必须加锁或暂停应用线程（这是传统 GC 停顿的核心原因之一）；
- 此外，传统 GC 移动对象后，需要遍历所有引用该对象的地方更新指针（全量重定位），耗时极长。

而 ZGC 的着色指针，本质是**把对象的「状态信息」从「对象头」转移到「指针本身」**，彻底解决并发修改的冲突问题。

## 二、着色指针的基础：指针的结构（以 64 位系统为例）

64 位系统中，一个指针（内存地址）原本是 64 位，但实际硬件支持的物理地址远小于 64 位（比如 x86-64 仅支持 48 位物理地址），剩下的位是「空闲位」。ZGC 正是利用这些**空闲位存储标记信息**。

### 1. 64 位指针的分区（ZGC 标准设计）

表格







|  位范围  |           用途           |                             说明                             |
| :------: | :----------------------: | :----------------------------------------------------------: |
| 0-41 位  |  实际内存地址（Offset）  | 指向对象所在的 Region 内的偏移地址，可支持 4TB 堆内存（2^42 = 4TB） |
| 42-45 位 | 着色标记位（Color Bits） | 核心：存储对象的状态（如是否被标记、是否被重定位、所属 Region 等） |
| 46-63 位 |     保留位 / 零填充      |              硬件要求高位必须为 0，避免地址无效              |

> 注：不同架构（如 ARM64）的位分区略有差异，但核心逻辑一致 —— 利用空闲位存储标记信息。

### 2. 「颜色」的本质：标记位的状态

ZGC 给 4 个着色位定义了不同的「颜色」（状态），核心状态包括：

- **未标记（White）**：对象未被 GC 标记为存活；
- **已标记（Marked）**：对象被 GC 标记为存活；
- **重定位中（Relocated）**：对象已被移动到新 Region，旧地址的指针需重映射到新地址；
- **可用（Free）**：对象所在的 Region 已被清理，可重新分配。

这些状态直接存储在指针中，无需修改对象本身。

## 三、着色指针的核心工作原理

### 1. 核心逻辑：「指针染色」代替「对象标记」

传统 GC 标记存活对象：遍历对象图 → 修改对象头的「标记位」→ 标记完成。

ZGC 标记存活对象：遍历对象图 → 修改**指针的着色位** → 标记完成。

关键差异：

- 修改指针的着色位是「无锁操作」（CPU 支持原子修改指定位），无需暂停应用线程；
- 应用线程访问对象时，CPU 的「内存管理单元（MMU）」会自动忽略着色位，只解析低 42 位的实际地址，不影响对象访问。

### 2. 核心能力 1：并发重定位（对象移动无停顿）

ZGC 移动对象（重定位）是实现低延迟的核心步骤，着色指针让这个过程完全并发：

#### 步骤拆解（以对象 A 为例）：

1. **准备阶段**：GC 选择包含 A 的 Region 进行回收，将 A 复制到新 Region，生成新地址 `new_ptr`；

2. **指针染色**：将旧地址 `old_ptr` 的着色位标记为「重定位中（Relocated）」，并在「重定位表」中记录 `old_ptr → new_ptr` 的映射关系；

3. 并发重映射

   ：

   - 应用线程访问 `old_ptr` 时，CPU 检测到着色位是「重定位中」，触发 ZGC 的「指针重映射陷阱（Remap Trap）」；
   - 陷阱处理逻辑自动将 `old_ptr` 替换为 `new_ptr`，并更新着色位为「已标记」；
   - 后续应用线程访问该指针时，直接使用新地址，无需再触发陷阱。

   

这个过程中，**应用线程和 GC 线程完全并发执行**，仅在「触发重映射陷阱」时有纳秒级的开销（远低于传统 GC 的毫秒级停顿）。

### 3. 核心能力 2：细粒度 Region 管理

ZGC 将堆划分为多个 Region，着色指针的高 4 位还能标记「对象所属的 Region ID」，实现：

- GC 回收时，只需处理「存活对象少的 Region」，无需扫描整个堆；
- 应用线程访问对象时，通过指针的 Region ID 直接定位到对应的 Region，无需全局查找；
- Region 的分配 / 释放通过着色位快速标记，无需加锁。

### 4. 硬件层面的支撑：MMU + 页表映射

着色指针能落地，依赖硬件的「内存管理单元（MMU）」和「页表（Page Table）」：

- MMU 负责将虚拟地址（指针）转换为物理地址，转换时会自动忽略着色位（只取低 42 位）；
- ZGC 通过修改页表，将「染色后的虚拟地址」映射到「实际物理地址」，确保指针的着色位不影响对象的正常访问。

简单类比：

- 指针的低 42 位是「门牌号」（实际地址），高 4 位是「门牌号上的备注（如 “已搬迁”）」；
- 快递员（MMU）只看「门牌号」送货，备注不影响送货，但快递员会根据备注提醒你 “地址已改”（重映射）。

## 四、着色指针带来的核心优势（对比传统 GC）

表格







|        特性        |     传统 GC（G1/CMS）      |        ZGC（着色指针）        |
| :----------------: | :------------------------: | :---------------------------: |
|      对象标记      | 修改对象头，需加锁 / 停顿  |   修改指针着色位，无锁并发    |
| 对象移动（重定位） | 全量更新引用，停顿百毫秒级 | 按需重映射，仅纳秒级陷阱开销  |
|     堆大小支持     | 最大 32GB（停顿随堆增大）  | 最大 16TB（停顿与堆大小无关） |
|     写屏障开销     |      高（维护记忆集）      |    低（仅检查指针着色位）     |
|     并发安全性     |     依赖锁 / 停顿保证      |  依赖硬件原子操作，无锁安全   |

## 五、注意事项：着色指针的限制

1. **仅支持 64 位系统**：32 位系统无足够的空闲位存储着色信息，ZGC 仅支持 64 位 JVM；
2. **硬件架构依赖**：需 CPU 支持 48 位以上的虚拟地址（x86-64、ARM64 均支持，老旧架构可能不支持）；
3. **指针压缩**：传统的 `-XX:+UseCompressedOops`（压缩指针）在 ZGC 中自动禁用，因为着色指针本身已利用了指针的高位空间。

### 总结

1. 着色指针的核心是「利用 64 位指针的空闲位存储对象状态」，将对象元数据从「对象头」转移到「指针」，彻底解决并发修改的冲突问题；
2. 通过「指针染色 + 硬件 MMU 支撑」，ZGC 实现了全并发的标记、重定位，停顿时间仅与 GC 根集大小相关，与堆大小无关；
3. 着色指针是 ZGC 支持 TB 级堆、毫秒级停顿的底层核心，也是其区别于传统 GC 的本质特征。
