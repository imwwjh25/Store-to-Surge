### Java ZGC（Z Garbage Collector）详解

ZGC 是 Oracle 在 JDK 11 中推出的一款**低延迟垃圾回收器**，设计目标是在任意堆大小（从几 GB 到数 TB）下，垃圾回收停顿时间不超过 10ms，主要面向大内存、低延迟的应用场景（如金融、电商核心系统）。

### 一、核心特性

1. **超低延迟**：停顿时间不依赖堆大小，仅与 GC 根集大小相关（如线程栈、本地变量），堆再大也能保持毫秒级停顿。
2. **并发执行**：大部分 GC 阶段（标记、重定位、清理）与应用线程并发执行，仅在极少数阶段有极短停顿。
3. **支持大堆**：可管理 TB 级堆内存（如 16TB），且性能不会显著下降。
4. **动态堆大小调整**：支持运行时动态调整堆的最小值（-Xms）和最大值（-Xmx）。
5. **基于着色指针（Colored Pointers）**：ZGC 的核心技术，通过在指针中嵌入额外信息（如对象状态、重定位信息），避免传统 GC 的写屏障开销，简化并发处理逻辑。
6. **Region 化内存管理**：将堆划分为大小固定的 Region（区域），Region 大小可动态调整（小 Region：2MB、中 Region：32MB、大 Region：N*2MB），支持细粒度的内存回收。

### 二、ZGC 工作流程（核心阶段）

ZGC 的垃圾回收过程分为 4 个主要阶段（大部分并发执行）：

1. **并发标记（Concurrent Mark）**：遍历对象图，标记存活对象，全程与应用线程并发，无停顿。
2. **并发重定位（Concurrent Relocate）**：选择部分 Region（如内存碎片多、存活对象少的），将其中存活对象复制到新 Region，更新指针指向新地址，仅在 “重定位开始” 和 “重定位结束” 有纳秒级停顿。
3. **并发重映射（Concurrent Remap）**：逐步更新应用线程中指向旧 Region 的指针到新地址，避免全量更新导致的停顿。
4. **并发清理（Concurrent Cleanup）**：清理空 Region，回收内存，供后续分配使用。

### 三、如何启用 ZGC

ZGC 在 JDK 11 中为实验特性，JDK 15 正式转正，启用命令如下：

#### 1. JDK 11-14（实验阶段）







```
java -XX:+UnlockExperimentalVMOptions -XX:+UseZGC -Xms4g -Xmx4g YourApplication
```

#### 2. JDK 15+（正式特性）




```
java -XX:+UseZGC -Xms8g -Xmx8g YourApplication
```

#### 关键参数说明

表格







|               参数                |                     作用                      |
| :-------------------------------: | :-------------------------------------------: |
|           `-XX:+UseZGC`           |     启用 ZGC（JDK15 + 无需解锁实验选项）      |
|            `-Xms/-Xmx`            | 设置堆初始值 / 最大值（ZGC 建议堆不小于 4GB） |
| `-XX:ZCollectionInterval=seconds` |     强制 GC 间隔（默认不强制，按需设置）      |
|       `-XX:ZHeapSize=size`        |            堆最大值（等价于 -Xmx）            |

### 四、ZGC 适用场景 & 不适用场景

#### ✅ 适用场景

- 大内存应用（堆 ≥ 8GB）：如大数据、分布式系统、中间件（Redis/JVM 版、MQ）。
- 低延迟要求：停顿时间要求 < 10ms 的核心业务（如支付、交易系统）。
- 多核 CPU 环境：ZGC 依赖多核并行执行，单核性能差。

#### ❌ 不适用场景

- 小堆内存（< 4GB）：ZGC 的并发机制有额外开销，小堆下性能不如 G1。
- 单核 / 少核 CPU：并发阶段无法并行，反而导致停顿变长。
- 对吞吐量极致追求：ZGC 为低延迟牺牲少量吞吐量（比 G1 低 5%-10%）。

### 五、ZGC vs G1（对比）





|    特性    |            ZGC             |              G1              |
| :--------: | :------------------------: | :--------------------------: |
|  停顿目标  |   < 10ms（不依赖堆大小）   | 100ms 左右（堆越大停顿越长） |
| 最大堆支持 |            16TB            |  约 32GB（堆越大性能越差）   |
|  核心技术  |     着色指针 + Region      |       记忆集 + Region        |
|   吞吐量   | 略低（牺牲吞吐量换低延迟） |             较高             |
|   成熟度   |    JDK15 转正，生态完善    |     JDK7 推出，极其成熟      |

### 总结

1. ZGC 是 Java 低延迟 GC 的核心方案，核心优势是**大堆下毫秒级停顿**，依赖着色指针和并发执行实现。
2. 启用 ZGC 需 JDK11+（JDK15+ 正式版），小堆 / 单核场景不建议使用，优先选 G1。
3. ZGC 适合大内存、低延迟的核心业务，牺牲少量吞吐量换取极致的停顿控制。
