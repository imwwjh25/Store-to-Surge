### 一、先理清 3 个核心概念（新手必看）

在动手前，先明确这 3 个关键知识点，否则代码写了也不懂原理：

1. **类加载器（ClassLoader）**：JVM 加载.class 文件到内存的工具，核心规则是「双亲委派模型」—— 加载类时先让父加载器加载，父加载器加载不到才自己加载；
2. **自定义类加载器**：继承 JDK 的`ClassLoader`，重写`findClass()`方法，实现自定义的类加载逻辑（比如从网络 / 加密文件加载类）；
3. **单例模式**：保证一个类只有一个实例，这里是让「自定义类加载器」本身只有一个实例（避免重复创建加载器导致类被多次加载）。

### 二、设计思路

目标：设计一个**单例的自定义类加载器**，且该加载器遵循「双亲委派模型」（指定父加载器）。

核心步骤：

1. 自定义类加载器继承`ClassLoader`，重写`findClass()`（核心加载逻辑）；
2. 给自定义加载器实现**线程安全的单例**（推荐枚举 / 双重检查锁）；
3. 在自定义加载器的构造方法中指定「父类加载器」（遵循双亲委派）；
4. 测试：用单例加载器加载自定义类，验证加载器唯一性 + 双亲委派规则。

### 三、完整实现代码（可直接运行）

#### 步骤 1：自定义类加载器（单例 + 指定父加载器）







```
import java.io.ByteArrayOutputStream;
import java.io.FileInputStream;
import java.io.IOException;
import java.nio.ByteBuffer;
import java.nio.channels.FileChannel;

/**
 * 单例模式的自定义类加载器
 * 核心：1. 单例 2. 指定父加载器 3. 重写findClass实现类加载
 */
public class SingletonCustomClassLoader extends ClassLoader {
    // 1. 单例核心：静态实例（volatile保证可见性）
    private static volatile SingletonCustomClassLoader INSTANCE;
    
    // 类文件的加载路径（可自定义，比如从指定文件夹加载.class）
    private final String classPath;

    // 2. 私有构造方法：指定父加载器 + 初始化类加载路径
    // parentClassLoader：传入的父加载器（遵循双亲委派）
    private SingletonCustomClassLoader(ClassLoader parentClassLoader, String classPath) {
        super(parentClassLoader); // 关键：指定父加载器（交给父类ClassLoader处理）
        this.classPath = classPath;
    }

    // 3. 双重检查锁实现线程安全的单例
    public static SingletonCustomClassLoader getInstance(String classPath) {
        if (INSTANCE == null) {
            synchronized (SingletonCustomClassLoader.class) {
                if (INSTANCE == null) {
                    // 父加载器指定为系统类加载器（AppClassLoader），也可自定义其他父加载器
                    ClassLoader parentLoader = ClassLoader.getSystemClassLoader();
                    INSTANCE = new SingletonCustomClassLoader(parentLoader, classPath);
                }
            }
        }
        return INSTANCE;
    }

    // 4. 核心：重写findClass（双亲委派中父加载器加载不到时，执行此方法）
    @Override
    protected Class<?> findClass(String className) throws ClassNotFoundException {
        try {
            // 步骤1：将类名转为文件路径（如com.test.Demo -> com/test/Demo.class）
            String classFileName = className.replace(".", "/") + ".class";
            String fullPath = classPath + "/" + classFileName;

            // 步骤2：读取.class文件的字节数组
            byte[] classBytes = loadClassBytes(fullPath);
            if (classBytes == null) {
                throw new ClassNotFoundException("类文件不存在：" + fullPath);
            }

            // 步骤3：调用父类的defineClass，将字节数组转为Class对象
            return defineClass(className, classBytes, 0, classBytes.length);
        } catch (IOException e) {
            throw new ClassNotFoundException("加载类失败：" + className, e);
        }
    }

    // 辅助方法：读取.class文件为字节数组
    private byte[] loadClassBytes(String path) throws IOException {
        try (FileInputStream fis = new FileInputStream(path);
             FileChannel channel = fis.getChannel()) {
            ByteBuffer buffer = ByteBuffer.allocate((int) channel.size());
            channel.read(buffer);
            return buffer.array();
        }
    }

    // 测试：防止反射破坏单例（可选，增强单例安全性）
    private SingletonCustomClassLoader() {
        super(ClassLoader.getSystemClassLoader());
        this.classPath = "";
    }
}
```

public class ClassLoaderTest {
    public static void main(String[] args) {
        // 1. 两次获取单例加载器，验证是否为同一个实例

            testClass.getMethod("sayHello").invoke(instance);

        }
    }

### 四、关键代码解释

1. **单例实现**：

   

   - 用`private static volatile`修饰实例，`volatile`防止指令重排导致的空指针；
   - 双重检查锁（DCL）保证线程安全，且只有第一次调用时创建实例；
   - 私有构造方法防止外部`new`，同时在构造方法中指定父加载器（`super(parentClassLoader)`）。

   

2. **父加载器指定**：

   

   - `ClassLoader`的构造方法支持传入父加载器，这里我们指定系统类加载器（`ClassLoader.getSystemClassLoader()`）；
   - 若不指定，JVM 会默认将当前类的加载器作为父加载器（比如启动类加载器 / 扩展类加载器）。

   

3. **自定义加载逻辑**：

   

   - 重写`findClass()`而非`loadClass()`：因为`loadClass()`包含双亲委派的核心逻辑，重写会破坏规则；`findClass()`是父加载器加载失败后才执行的自定义逻辑；
   - `loadClassBytes()`：读取指定路径下的.class 文件为字节数组，`defineClass()`将字节数组转为 Class 对象（这是 JVM 加载类的核心步骤）。

   

### 五、常见问题 & 避坑点

1. **为什么不重写 loadClass ()？**

   答：`loadClass()`的核心逻辑是「双亲委派」：


   

   

   

   ```
   protected Class<?> loadClass(String name, boolean resolve) throws ClassNotFoundException {
       synchronized (getClassLoadingLock(name)) {
           // 1. 检查是否已加载
           Class<?> c = findLoadedClass(name);
           if (c == null) {
               long t0 = System.nanoTime();
               try {
                   // 2. 先让父加载器加载
                   if (parent != null) {
                       c = parent.loadClass(name, false);
                   } else {
                       c = findBootstrapClassOrNull(name);
                   }
               } catch (ClassNotFoundException e) {
                   // 父加载器加载失败，执行自定义findClass
               }
               if (c == null) {
                   long t1 = System.nanoTime();
                   c = findClass(name); // 自定义加载逻辑
               }
           }
           if (resolve) {
               resolveClass(c);
           }
           return c;
       }
   }
   ```

   

   重写`loadClass()`会破坏双亲委派，导致类被重复加载（比如 JDK 的`java.lang.String`被自定义加载器加载，引发安全问题）。

   

2. **单例加载器的线程安全？**

   答：双重检查锁 +`volatile`是基础，若要更安全，可改用**枚举单例**（天然防反射 / 序列化破坏）：

   

   

   ```
   public enum EnumSingletonClassLoader {
       INSTANCE;
       
       private final SingletonCustomClassLoader loader;
       
       EnumSingletonClassLoader() {
           loader = new SingletonCustomClassLoader(ClassLoader.getSystemClassLoader(), "D:/test");
       }
       
       public SingletonCustomClassLoader getLoader() {
           return loader;
       }
   }
   // 使用：EnumSingletonClassLoader.INSTANCE.getLoader()
   ```

   

3. **类加载器的命名空间？**

   答：同一个类被不同加载器加载，会被 JVM 视为不同的类（即使字节码相同）。单例加载器保证了类只会被一个加载器加载，避免类重复定义异常。

   

### 总结

1. 核心设计要点：

   - 单例：自定义类加载器用「双重检查锁 / 枚举」实现线程安全的单例，避免重复创建加载器；
   - 父加载器：通过构造方法`super(parentClassLoader)`指定，遵循双亲委派模型；
   - 自定义加载：重写`findClass()`实现.class 文件读取，不破坏双亲委派。

   

2. 关键避坑 ：

   - 不重写`loadClass()`，只重写`findClass()`；
   - 单例需加`volatile`保证线程安全，或用枚举更稳妥；
   - 父加载器建议指定系统类加载器，避免加载逻辑混乱。
