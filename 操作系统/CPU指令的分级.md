CPU 的特权指令通常对应**处理器的特权级别**，而非直接对指令分级，常见的是 “Ring 0 到 Ring 3” 四级特权模型，其中只有高特权级（如 Ring 0）能执行特权指令。

### 一、核心特权级别模型：四级（Ring 0 - Ring 3）

这是 x86 架构等主流 CPU 采用的经典模型，特权级别从 0 到 3 依次降低，不同级别对应不同的指令执行权限和资源访问范围。

| 特权级别（Ring） | 权限等级 | 核心作用与使用场景                                           |
| ---------------- | -------- | ------------------------------------------------------------ |
| **Ring 0**       | 最高     | 称为 “内核态”，可执行所有特权指令（如操作内存管理单元、控制 I/O 设备、修改 CPU 状态）。仅操作系统内核代码运行在此级别，确保系统核心功能安全。 |
| **Ring 1**       | 次高     | 设计用于驱动程序或中间层服务，可访问部分硬件资源，但权限低于 Ring 0。实际操作系统（如 Windows、Linux）极少使用，通常将其与 Ring 0 合并管理。 |
| **Ring 2**       | 次低     | 功能与 Ring 1 类似，定位为更细分的中间特权层，同样未被主流操作系统广泛采用，处于 “闲置” 状态。 |
| **Ring 3**       | 最低     | 称为 “用户态”，仅能执行非特权指令（如普通数据运算、调用系统 API），无法直接访问硬件或修改系统核心参数。所有用户应用程序（如浏览器、办公软件）均运行在此级别，避免误操作影响系统稳定性。 |

### 二、关键补充：特权指令与特权级的关系

1. **特权指令的定义**：特指只能在高特权级（通常是 Ring 0）执行的指令，若在低特权级（如 Ring 3）尝试执行，CPU 会触发 “特权级异常”，终止当前程序并将控制权交还给操作系统内核。

2. 常见特权指令举例：

   - 内存相关：修改页表寄存器（控制虚拟内存映射）、启用 / 禁用内存保护。
   - 硬件控制：读写 I/O 端口（操作磁盘、网卡等设备）、设置 CPU 中断屏蔽位。
   - 系统状态：修改 CPU 特权级寄存器、初始化系统时钟。

### 三、简化模型：主流系统的实际应用

尽管 CPU 支持四级特权，但 Windows、Linux、macOS 等主流操作系统均采用 “**两级简化模型**”，仅使用 Ring 0（内核态）和 Ring 3（用户态）：

- 原因：四级模型的细分特权层（Ring 1、Ring 2）会增加系统设计复杂度，而两级模型已能满足 “内核安全管控 + 用户程序隔离” 的核心需求，兼顾安全性与效率。
- 效果：用户程序需访问硬件或执行特权操作时，必须通过 “系统调用”（如 Linux 的`syscall`、Windows 的`Win32 API`）切换到 Ring 0，由内核代执行，完成后再切回 Ring 3，确保权限严格隔离。
