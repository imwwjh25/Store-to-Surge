Docker 实现隔离的核心原理是利用 Linux 内核的三大技术，通过对进程、文件系统、网络等资源的隔离，让容器内的应用仿佛运行在独立环境中。具体如下：

### 1. 命名空间（Namespaces）

- **作用**：隔离进程的 “视线”，让每个容器只能看到自己的资源（如进程、网络、文件系统等）。

- 关键类型：

    - PID Namespace：隔离进程 ID，容器内的进程看不到宿主机或其他容器的进程。
    - Network Namespace：为容器创建独立的网络栈（网卡、IP、端口等），与宿主机和其他容器隔离。
    - Mount Namespace：让容器拥有独立的文件系统挂载视图，容器内的挂载操作不影响宿主机。
    - UTS Namespace：隔离主机名和域名，容器可设置自己的主机名。
    - User Namespace：隔离用户和组 ID，容器内的 root 用户在宿主机上可能只是普通用户，提升安全性。

### 2. 控制组（Control Groups，cgroups）

- **作用**：限制容器对资源（CPU、内存、磁盘 I/O 等）的使用，防止单个容器过度占用资源影响其他容器或宿主机。
- **举例**：通过 cgroups 可限制容器最多使用 1 核 CPU 和 1GB 内存，避免资源争抢。

### 3. 联合文件系统（UnionFS）

- **作用**：为容器提供轻量级的独立文件系统，同时实现文件层的复用和隔离。
- **原理**：将多个目录（镜像层和容器层）合并为一个虚拟文件系统，容器的修改仅在自己的读写层生效，不影响底层镜像，节省存储空间并提高启动速度。

通过这三大技术的结合，Docker 实现了容器的隔离性、资源限制和轻量级特性，既保证了应用运行环境的独立性，又比传统虚拟机更高效。
