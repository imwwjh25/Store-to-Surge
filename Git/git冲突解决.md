# FAT环境多分支并行开发，push推送被拒绝问题
## 问题描述
> 现在我还有个问题，就是我们 fat 环境中有很多个分支：分支1、分支2、分支3，我的分支是分支1。我很早就在本地创建了分支并且修改了代码，但是之后别人也在自己的分支上提交了代码，现在我没有更新项目，我再 push 的时候就会被拒绝。

## 核心概念区分
> 这里有一个很容易混淆点：
> 同事向**分支2、分支3**提交代码，**并不会导致我分支1 push被拒绝**，各个分支之间提交互相隔离。
> push 被拒绝的本质：**远程 `origin/分支1` 已经存在新的提交，本地的分支1版本落后于远程分支1**。一般是其他同事也往分支1推送过代码。

## push被拒绝两种场景
### 场景1：分支1是多人协作共享分支（高频）
同事和你共用分支1，同事已经先把代码push到远程 `origin/分支1`。
你本地长期没有拉取更新，本地分支1缺少远程上新的commit，执行push时Git直接拒绝推送，防止覆盖远程已有提交。

> ⚠️ 注意：同事提交到分支2、分支3，只是其他分支的变更，不会造成分支1 push失败。
> 但后续合并到master主干的时候，会产生大量代码冲突。

### 场景2：分支1仅自己单人开发，仍然出现push拒绝
这种情况较少，一般是本地做过rebase操作，本地提交历史与远程提交历史不一致，Git校验不通过。

## 解决方案
### 方案A：多人共享分支（推荐使用merge，禁止rebase）
```bash
# 获取远程仓库全部最新信息，不会自动合并代码
git fetch origin

# 切换到自己的工作分支
git checkout 分支1

# 将远程分支1的新提交合并到本地分支1，出现冲突手动解决
git merge origin/分支1

# 冲突处理完成，提交变更
git add .
git commit

# 推送代码到远程
git push origin 分支1
