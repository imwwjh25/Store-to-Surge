### 一、核心区别（由浅入深）

#### 1. 最直观的差异：是否计算相关性得分

- **query（查询）**：不仅判断文档是否匹配，还会计算一个 **相关性得分（_score）**（范围 0~1），表示文档与查询条件的匹配程度，最终按得分排序。
- **filter（过滤）**：只做 “是 / 否” 的判断（匹配或不匹配），**不计算得分**，结果也不排序（默认按文档 ID）。

#### 2. 具体特性对比

表格







|         特性         |             query（查询）             |                   filter（过滤）                   |
| :------------------: | :-----------------------------------: | :------------------------------------------------: |
|       核心目标       |     全文检索、精准匹配（需排序）      |          条件过滤（仅保留符合条件的文档）          |
| 相关性得分（_score） |      计算并返回得分（用于排序）       |                不计算（得分恒为 0）                |
|       缓存机制       |  不缓存（查询条件多变，缓存收益低）   |          缓存（过滤条件固定，缓存收益高）          |
|         性能         |        相对较慢（需计算得分）         |             极快（仅判断 + 缓存复用）              |
|       常用场景       | 全文检索（如 “搜索包含‘手机’的商品”） | 范围过滤、精确过滤（如 “价格> 5000”“分类 = 手机”） |
|       常用语法       |    `match`、`term`（query 上下文）    |   `bool.filter`、`constant_score`、`filter`聚合    |

#### 3. 代码示例：直观对比效果

我们用「电商商品检索」场景，分别演示 `query` 和 `filter` 的使用，你能直接看到差异。

##### 步骤 1：创建索引 + 插入测试数据

json











```
# 创建商品索引
PUT /product_index
{
  "mappings": {
    "properties": {
      "name": { "type": "text" },       // 全文检索
      "category": { "type": "keyword" },// 精确过滤
      "price": { "type": "double" }     // 范围过滤
    }
  }
}

# 插入测试数据
POST /product_index/_bulk
{"index":{"_id":1}}
{"name":"小米14 Pro 手机","category":"手机","price":4999}
{"index":{"_id":2}}
{"name":"华为Mate60 Pro 手机","category":"手机","price":5999}
{"index":{"_id":3}}
{"name":"苹果iPad Pro 平板","category":"平板","price":7999}
{"index":{"_id":4}}
{"name":"小米平板6 Pro 平板","category":"平板","price":2999}
```

##### 步骤 2：测试 1 - query（查询）：计算得分，按匹配度排序

json











```
# 用match query搜索“小米”相关商品
GET /product_index/_search
{
  "query": {
    "match": { "name": "小米" }
  }
}

# 预期结果（重点看_score）：
{
  "hits": [
    { "_id": "1", "_score": 0.6931, "source": { "name": "小米14 Pro 手机" } },
    { "_id": "4", "_score": 0.6931, "source": { "name": "小米平板6 Pro 平板" } }
  ]
}
```

- 结果说明：返回包含 “小米” 的文档，且每个文档有 `_score`（相关性得分），按得分排序。

##### 步骤 3：测试 2 - filter（过滤）：不计算得分，结果无排序

json











```
# 用bool.filter过滤“价格>5000”的商品
GET /product_index/_search
{
  "query": {
    "bool": {
      "filter": [  // 过滤条件
        { "range": { "price": { "gt": 5000 } } }
      ]
    }
  }
}

# 预期结果（重点看_score）：
{
  "hits": [
    { "_id": "2", "_score": 0.0, "source": { "price": 5999 } },
    { "_id": "3", "_score": 0.0, "source": { "price": 7999 } }
  ]
}
```

- 结果说明：只返回价格 > 5000 的文档，`_score` 恒为 0，结果按文档 ID 排序（无匹配度排序）。

##### 步骤 4：最佳实践 - query + filter 结合使用

实际场景中，常把 “全文检索（query）” 和 “条件过滤（filter）” 结合，兼顾精准度和性能：

json











```
# 需求：搜索“小米”相关商品，且价格>3000
GET /product_index/_search
{
  "query": {
    "bool": {
      "must": [  // query部分：计算得分
        { "match": { "name": "小米" } }
      ],
      "filter": [ // filter部分：仅过滤，不计算得分
        { "range": { "price": { "gt": 3000 } } }
      ]
    }
  }
}

# 预期结果：仅返回“小米14 Pro 手机”（价格4999>3000），且有_score。
```

#### 4. 缓存机制的直观理解

- **filter 缓存**：ES 会把 filter 的结果（文档 ID 列表）缓存到内存，当再次执行相同的 filter 条件时，直接复用缓存结果，无需重新计算，性能提升显著（比如 “过滤分类 = 手机” 的条件，多次查询都能复用缓存）。
- **query 无缓存**：因为 query 要计算得分，而得分与查询条件、文档内容强相关，缓存收益低，所以 ES 不会缓存 query 结果。

### 总结

1. **核心差异**：`query` 计算相关性得分（用于排序）、不缓存；`filter` 不计算得分、缓存结果（性能更快）。
2. **使用场景**：`query` 用于需要全文检索 / 匹配度排序的场景；`filter` 用于精确过滤 / 范围过滤（如价格、分类、日期）。
3. **最佳实践**：实际开发中优先用 `bool` 组合 `must（query）+ filter`，既满足检索需求，又利用 filter 缓存提升性能。
