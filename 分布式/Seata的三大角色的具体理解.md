# 一句话本质区别（背这个）

- **TM：发起全局事务的人（业务方）**
- **TC：管全局事务的人（独立协调器）**
- **RM：管本地数据库事务的人（数据库代理）**

------

# 用一个「公司审批流程」类比（秒懂）

假设：你要做一个**跨部门审批**（分布式事务），

需要：部门 A、部门 B、部门 C 一起同意，才算通过。

## 1. TM（Transaction Manager）= **申请人 / 发起人**

- 是谁：**你的业务代码**（加了 `@GlobalTransactional` 的方法）

- 干什么：

  - 决定**什么时候开始**全局事务
  - 决定**最后是提交还是回滚**
  - 只管「开始 / 结束」，不管中间细节

  

- **本质：业务层的事务入口**

> 你说：我要下单 → TM 向 TC 说：开一个全局事务！

------

## 2. TC（Transaction Coordinator）= **独立审批中心**

- 是谁：**Seata Server（单独启动的服务）**

- 干什么：

  - 给全局事务发**全局 ID（XID）**
  - 记录所有参与的分支事务
  - 统一指挥：**全部提交 / 全部回滚**
  - 监控所有分支状态

  

- **本质：分布式事务的大脑、总指挥**

> TC 就是那个**坐在中间，谁都听它的**角色。

------

## 3. RM（Resource Manager）= **各部门办事员 / 数据库代理**

- 是谁：**每个微服务里的数据库连接代理**

- 干什么：

  - 执行**本地 SQL**
  - 记录 undo_log
  - 本地提交 / 回滚
  - 向 TC 汇报：我这步成没成

  

- **本质：操作实际资源（DB）的执行者**

> RM 就是真正**操作数据库**的那个。

------

# 三者关系（最清晰的流程）

1. TM（你的业务）

   

   → 向 TC 申请：开全局事务！

2. TC

   

   → 给一个 XID，说：你们都用这个 ID

3. 各个微服务里的 

   RM

   

   → 带着 XID 操作数据库

   

   → 向 TC 注册：我是分支 1、我是分支 2

4. 业务执行完

   

   → 

   TM

    告诉 TC：提交 / 回滚

5. TC

    命令所有 

   RM

   

   → 一起提交 或 一起回滚

------

# 本质区别总结（面试满分版）

## 1. 从「职责」看

- **TM：管开始和结束**（发起、决定提交 / 回滚）
- **TC：管全局协调**（状态、指令、统一控制）
- **RM：管本地执行**（操作 DB、执行分支提交 / 回滚）

## 2. 从「所在位置」看

- **TM 在你的业务代码里**
- **TC 是独立中间件服务（Seata Server）**
- **RM 在每个微服务的数据源代理里**

## 3. 从「控制层级」看

- **TM：应用层控制**
- **TC：全局事务控制**
- **RM：本地资源控制**

------

# 最精炼三句（面试官最爱）

- **TM 是事务发起人，管什么时候开始、什么时候结束。**
- **TC 是事务协调器，管全局状态、发统一指令。**
- **RM 是资源执行者，管本地数据库的实际提交与回滚。**
