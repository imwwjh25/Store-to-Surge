# 核心一句话

- **2PC**：传统强一致性分布式事务协议，**阻塞、性能差、依赖数据库原生支持**。
- **Seata AT**：基于**二阶段思想**但做了**大幅优化**的**非侵入、高性能、最终一致**分布式事务方案。

------

# 一、本质区别

1. **2PC**

   

   - 是**协议规范**（XA 就是典型实现）
   - 强一致性，**阻塞式**
   - 依赖数据库底层支持

   

2. **Seata AT**

   

   - 是**Seata 实现的一种模式**
   - 基于**二阶段思想**，但**不是标准 2PC**
   - **无侵入、自动生成 SQL、性能高**

   

------

# 二、流程区别（最关键）

## 1）2PC 两阶段

1. 第一阶段（prepare）

   - 所有参与者锁定资源、redo/undo 就绪
   - **阻塞等待**协调者指令

   

2. 第二阶段（commit/rollback）

   - 协调者下发统一指令
   - 所有库一起提交或回滚

   

**缺点：**

- 长阻塞、长锁、吞吐量极低
- 协调者单点故障风险大
- 不适合高并发

------

## 2）Seata AT 两阶段

1. 一阶段（prepare）

   - **本地事务直接提交**！不阻塞
   - Seata 自动记录 **undo_log**
   - 本地锁立即释放

   

2. 二阶段（commit/rollback）

   - commit：异步删除 undo_log
   - rollback：通过 undo_log **自动回滚**

   

**关键点：**

- **一阶段就提交本地事务**
- 不是阻塞式，**锁时间极短**
- 业务无侵入，不用写事务代码

------

# 三、详细对比表（面试直接背）








|     维度     |        2PC / XA         |         Seata AT         |
| :----------: | :---------------------: | :----------------------: |
|  **一致性**  |         强一致          |         最终一致         |
|  **锁机制**  |   全程锁定资源，阻塞    |    一阶段提交，锁极短    |
|   **性能**   |    差，不适合高并发     | 高吞吐，性能接近本地事务 |
|  **侵入性**  | 高，需数据库 / 驱动支持 |     0 侵入，只加注解     |
|   **实现**   |     数据库原生支持      |  基于 undo_log 自动代理  |
|   **阻塞**   |         会阻塞          |        基本不阻塞        |
| **适用场景** |  金融核心、强一致要求   |   互联网微服务、高并发   |

------

# 四、最精炼总结（面试官最爱）

- **2PC**：强一致、阻塞、性能差、依赖数据库底层。
- **Seata AT**：借鉴二阶段思想，**一阶段提交本地事务**，通过 undo_log 实现自动回滚，**无侵入、高性能、适合微服务**。
